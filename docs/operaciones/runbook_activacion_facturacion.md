# Activación de emisión electrónica por restaurante

**Estado:** guía preparada; no activar hasta cerrar los pendientes de `emision_electronica.md` y obtener una CDR real de ensayo controlado. Repetir estos pasos por cada restaurante. Nunca usar el RUC, certificado o series de otro restaurante.

1. **Confirmar datos y habilitación.** Con el titular y su contador, verificar RUC activo y habido, condición de emisor electrónico, régimen, afectación IGV de cada producto, tasa aplicable, razón social, dirección fiscal, ubigeo y series fiscales B/F asignadas. Confirmar que esas series no se usaron antes en otro sistema. Instalar manualmente el esquema: en una base nueva usar `Database/008_mesora_instalacion_oficial.sql`; en una base MESORA existente anterior usar solo `Database/011_emision_electronica.sql` y las migraciones posteriores que correspondan, tras respaldo. No ejecutar dos veces las tablas nuevas.
2. **Preparar certificado y acceso técnico.** El administrador del servidor guarda el CDT vigente `.p12` fuera de `C:\xampp\htdocs\MESORA`, del directorio público y del repositorio, con lectura limitada al proceso PHP. Configura para el ID exacto del restaurante `SUNAT_<ID>_P12_PATH`, `SUNAT_<ID>_P12_PASSWORD`, `SUNAT_<ID>_USUARIO` (RUC seguido del usuario secundario autorizado) y `SUNAT_<ID>_CLAVE` (contraseña de ese usuario secundario). No solicitar ni guardar la Clave SOL principal en MESORA. Verificar PHP con DOM, OpenSSL, cURL, PharData, Composer `vendor/`, salida HTTPS y una tarea programada fiable.
3. **Habilitar solo ese restaurante.** En **Emisión electrónica**, entrar como admin del restaurante, completar RUC, razón social, dirección, ubigeo, régimen, tasa IGV y series, y guardar primero en `pruebas`. El administrador del servidor añade `SUNAT_PRODUCCION_AUTORIZADA_<ID>=1` únicamente tras las verificaciones anteriores. Después, en la misma pantalla del restaurante, seleccionar `produccion` y guardar. Si falta certificado o permiso, el sistema rechaza el cambio. Los otros restaurantes conservan su modo.
4. **Primera venta controlada.** Abrir caja, cobrar un pedido pequeño y preparar su boleta o factura con cliente correcto. Anotar ID de pedido e ID fiscal. Ejecutar `php bin/enviar_emision.php --enviar <ID_RESTAURANTE> <ID_DOCUMENTO>` desde un entorno con `DB_NAME` explícito y correcto. Para boleta, ejecutar después `--consultar` hasta resolver el ticket; para factura incierta, consultar CDR antes de cualquier reintento. Verificar que el XML firmado corresponde a RUC, serie, número, cliente, líneas y total; comprobar la CDR descargada y que el estado del restaurante sea `aceptado` o `aceptado_observado`. Revisar el PDF con QR y cotejar el comprobante en SUNAT. Solo entonces programar `--pendientes <ID_RESTAURANTE>` periódicamente y permitir uso cotidiano.
5. **Si falla.** El cobro ya registrado no se repite ni se cobra otra vez al cliente. Un estado `incierto` exige consulta y conciliación; nunca crear otro correlativo ni reenviar a ciegas. Si el documento fue rechazado, conservar XML/CDR y usar el procedimiento explícito de corrección y reemisión; si fue aceptado, cualquier corrección o anulación requiere el circuito fiscal de nota/baja aplicable. Si no se logra confirmar una CDR real, volver ese restaurante a `desactivado`, documentar el incidente y usar el canal fiscal de contingencia habilitado, conciliando luego el pedido sin duplicar el cobro.

**Control de salida:** RUC y CDT vigentes, configuración aislada, tarea programada operativa, prueba de aceptación real y cierre del NO-GO multitenant. Mientras falte cualquiera, mantener `produccion` desactivado.
